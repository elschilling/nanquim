# Nanquim v0.1.0-alpha.1

`v0.1.0-alpha.1` establishes the first versioned prerelease baseline for
Nanquim. It is intended for evaluation, workflow testing, and compatibility
feedback rather than irreplaceable production drawings.

## Highlights

- Draw and modify SVG geometry through toolbar and terminal workflows.
- Organize drawings with collections, groups, and reusable blocks.
- Prepare sheets in Paper Space and export printable PDF output.
- Keep model geometry correctly positioned in live Paper viewports and their
  standalone SVG/PDF output, including stroke-only lines in PDF viewports.
- Import and export SVG and common DXF drawing entities.
- Open files from Firefox's chooser without a repeated welcome-screen dismissal
  error.
- Explore the experimental Geometry Nodes editor for non-destructive
  procedural SVG geometry.
- Search the in-application command reference, including visual command
  illustrations.

## Compatibility

- Application version: `0.1.0-alpha.1`.
- Native Nanquim SVG saves remain document schema 2.
- Geometry Nodes metadata remains schema 1.
- This release does not intentionally change either saved-data schema.
- Desktop Chromium stable and the previous stable release are the primary beta
  target. Firefox stable and ESR use the portable upload/download workflow.
  Safari/WebKit is best-effort and receives a manual prerelease check when a
  test machine is available; mobile and touch-first editing are not supported.
- Persistent file handles depend on a secure context and the browser File
  System Access API. Upload and download fallbacks remain the portable path.

See the [browser and file-API support policy](https://github.com/elschilling/nanquim/blob/v0.1.0-alpha.1/docs/browser-support.md)
for exact tiers, fallbacks, and qualification requirements.

## Known limitations

- This is an alpha. Keep independent copies of important SVG and DXF files.
- Native save/reopen coverage is not yet complete for every Paper Space
  annotation, imported SVG definition, specialized entity, or historical file.
- Paper SVG/PDF output may omit nested Block instances or imported definitions
  whose external definitions are not embedded in the Paper file. Keep the
  editable source drawing and inspect exported files.
- DXF exchange supports common drawing entities, not every entity or vendor
  extension, and interoperability profiles are still being qualified.
- Many interactive CAD commands still need full lifecycle and real-browser
  regression coverage.
- Geometry Nodes is experimental and its editing, persistence, and export edge
  cases are still under active testing.
- Browser clipboard, file permissions, and persistent handles vary by browser
  and may require explicit user permission.
- System-only text families are not portable, and Fira Code Italic may render
  synthetically in the browser but upright in PDF output. Use a bundled
  normal/italic variant listed in the asset inventory when exact output parity
  matters.

## Qualification record

The functional release candidate was commit
[`3876106df38313ade821987570a79120cb1ff042`](https://github.com/elschilling/nanquim/commit/3876106df38313ade821987570a79120cb1ff042).
Its protected-branch [CI run](https://github.com/elschilling/nanquim/actions/runs/32396829477)
passed 178 tests across 20 files, the production build, and the high-severity
dependency audit. Vercel deployed that exact commit successfully at
the protected immutable URL
`nanquim-nsj3waj0z-elschillings-projects.vercel.app`, and the public
[`nanquim.vercel.app`](https://nanquim.vercel.app/) alias served the same
candidate.

Production qualification ran on Fedora Linux 44 Workstation on 2026-08-20:

- Chromium `151.0.7922.137`, at 1280×800, showed the expected application
  version without layout overflow, runtime errors, or failed requests. The
  exact-candidate workflow created a line and a rectangle from
  typed dimensions, selected geometry, completed Undo/Redo, downloaded and
  reopened a native schema-v2 SVG with collection ownership intact, created an
  A4 Paper viewport, and produced standalone Paper SVG and a valid one-page A4
  PDF. Independent PDF raster inspection confirmed that both the line and
  rectangle were painted. A broader run before the isolated PDF-only fix also
  covered 960×720 layout, Help, and allowed/denied clipboard paths cleanly.
- Firefox `153.0.3`, at 1280×800 and 960×720, passed 28 final-candidate startup,
  layout, font, and native-SVG assertions without a console, page, request, or
  HTTP error. Native SVG was opened through the real Welcome-screen file chooser;
  the overlay completed dismissal once, the document restored its collections,
  geometry, Paper data, Block, and Geometry Nodes metadata, and no persistent
  file handle was retained, as expected for Firefox. A broader 47-assertion run
  before the isolated PDF-only fix also covered Help and DXF import cleanly.

This alpha qualifies the installed Chromium and Firefox builds above. The
full current-and-previous Chromium, current-and-ESR Firefox, direct persistent
file-handle, and best-effort Safari matrix remains a `v0.1.0-beta.1` gate.
Firefox operating-system download completion was not automated because the
headless WebDriver BiDi harness could not capture even an isolated Blob
download; Chromium's portable download/reopen path and Firefox's real
file-input paths were verified instead.

## Feedback

Report reproducible problems at
<https://github.com/elschilling/nanquim/issues>. Include the browser and
operating-system versions, exact steps, expected and actual results, relevant
console errors, and a small shareable fixture when possible. Remove private or
sensitive drawing content before attaching a file.
